Export and restore safely

Create a validated snapshot, make one reversible memory change, stop all database users, restore, and prove the previous state returned.

Outcome and prerequisites

You will prove a full SQLite snapshot can restore prior memory state without handling secret values. Choose a new destination path that does not exist. Keep the terminal open so you can record the test memory ID.

This changes the active database

The tutorial is designed to be reversible and Synapse creates a pre-restore backup, but restore is still a real database replacement. Read every step and do not substitute a production backup you have not separately preserved.

  1. Check the active database

    shell 
    synapse path
synapse data check

    Integrity must report ok. If it does not, stop here and follow the corruption guidance in Troubleshooting.

  2. Create a fresh export

    shell 
    backup="$HOME/Desktop/synapsetutorialbackup.db"
test ! -e "$backup"
synapse data export "$backup"

    Synapse writes a consistent compact snapshot, secures it, opens it read-only, and validates it before returning success.

  3. Add one post-export memory

    shell 
    printf '%s
' 'This entry exists only after the tutorial export.' \
  | synapse memory add synapserecovery
synapse memory list synapserecovery

    Record the returned ID. This entry is the marker that should disappear after restoration.

  4. Stop every database user

    Quit the Synapse desktop app. Close all connected Codex and Claude Code sessions so their synapse mcp child processes exit. A normal CLI command releases its shared lock when it finishes.

    If you intentionally leave a connected session open, the next step should refuse with a message telling you to close the app and connected tools. Do not work around the lock.

  5. Restore the export

    shell 
    synapse data restore "$backup"

    The command validates the source and current database, acquires the exclusive lock, creates an automatic restore recovery snapshot of the current state, then atomically replaces the database.

  6. Verify the earlier state

    shell 
    synapse data check
synapse memory list synapserecovery

    Integrity should be ok, and the post-export marker should be absent. Reopen the desktop app and connected tools only after this verification.

Understand what did not move

Keychain values are not inside the export. On the same Mac, restored vault metadata still points at the existing items. On another Mac, recreate each expected value with synapse secret set.

Keep the export if it is part of your backup plan. Otherwise, move it to Trash after you are satisfied with the restore. The automatic pre-restore snapshot remains in the Synapse backups directory until you manage it deliberately.
