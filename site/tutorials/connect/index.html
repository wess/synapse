Install and connect your first tools

Go from the notarized archive to a working local MCP connection and verify memory from the app, CLI, and developer tool.

Outcome and prerequisites

You will install Synaps in Applications, install its user CLI, connect at least one supported developer tool, store a harmless test memory, and verify that the same record is visible through three surfaces.

  • Apple-silicon Mac running macOS 13 or later.
  • Codex, Claude Code, or both installed and available on PATH.
  • The latest synaps.zip release archive.

  1. Move and open the app

    Extract synaps.zip, move synaps.app to Applications, then open it. macOS should accept the notarized Developer ID application without a security workaround.

    Choose the permanent location now

    The CLI installed from a packaged app launches the executable inside that signed bundle. Install it only after the app is where you intend to keep it.

  2. Install the CLI

    Open Synaps Settings and choose Install CLI. Then open a new terminal:

    shell 
    synaps version
synaps path

    If the shell cannot find Synaps, add ~/.local/bin to PATH and start another shell. The path output should point at the same data directory the app uses.

  3. Connect a detected tool

    Return to the dashboard. Choose Connect beside Codex or Claude Code. The row should move from detected to connected. Connect the second tool too if it is installed.

    Synaps registers ~/.local/bin/synaps mcp at user scope and adds a managed memory instruction block. Existing configuration and instruction text remain in place; changed existing files receive .synapsbackup siblings.

  4. Restart the developer tool

    Close and reopen the connected tool so it loads the new MCP server. Inspect its available tools or ask it what Synaps tools are available. The answer should include remember, recall, and vaultstatus.

  5. Store a test memory

    Tell the connected tool:

    Remember this confirmed tutorial convention: documentation examples use the source label synapstutorial.

    It should call remember and report a stored numeric ID. Do not use a secret or sensitive value for this check.

  6. Verify through the CLI and app

    shell 
    synaps memory list synapstutorial
synaps memory list synapstutorial --json

    Open the Synaps Memories screen and search for synapstutorial. Confirm the exact body and source match. At this point the developer tool, CLI, and desktop app are reading one local store.

Next step

Continue with Carry one decision between tools to verify a real cross-session handoff. If a tool row becomes disconnected after moving or rebuilding Synaps, choose Repair; the app recognizes stale executable paths.
